# Боты

Простые эвристические боты для добора до 4 игроков и отладки. Цель — не выиграть против людей, а играть **правдоподобно**, чтобы партии можно было прогонять с неполным составом.

## 1. Интерфейс

```ts
interface Bot {
  /**
   * Получает отфильтрованный state с точки зрения бота
   * (как любой клиент) и возвращает Action.
   */
  decide(state: FilteredGameState): Action;
  
  /**
   * Вызывается когда бот должен ответить (PROPOSAL_ACCEPT/REJECT,
   * FIGHT_ALLY_ACCEPT/DECLINE и т.д.).
   * decide() покрывает все случаи — отдельный метод не нужен.
   */
}
```

Боты — это полноценные игроки в игре (`PlayerState.isBot: true`). Они живут на host'е, host вызывает `bot.decide(filterStateForPlayer(state, bot.playerId))` каждый раз, когда от бота ожидается действие.

## 2. Эвристики

### 2.1 Общие принципы

- **Самосохранение**: избегать смерти. Игрок без сознания и при жажде = смерть.
- **Бережливость**: не использовать одноразовые припасы зря.
- **Лёгкая социальность**: помогать другу (если бот знает, кто его друг), мешать врагу — но без манипуляций (бот не блефует).
- **Без переговоров**: бот не отправляет и не понимает сообщения; в драке решения принимает по своему состоянию.

### 2.2 Морфологический подход

Декомпозиция по подфазам. На каждую подфазу — эвристика возврата Action.

#### Morning: выбор припаса

Из имеющихся карт берёт по приоритету:
1. `water` если нет воды в припасах.
2. `first_aid` если есть свои ранения или у друга ранения.
3. `umbrella` если нет.
4. `oar` если ещё нет.
5. `life_ring` если ещё нет.
6. `compass` если бот ближе всех к корме.
7. Любое оружие (`hook` > `knife` > `club`) если силы маловато.
8. Любая ценность (можно учитывать характер-множитель).
9. Иначе — любая.

#### Day: выбор действия

Решает по приоритету:
1. Если у меня ранение и есть аптечка → **first_aid на себя** (или на друга, если у друга >= 2 ранений).
2. Если у врага открытый ценный припас (вода) и я могу его взять → **ограбить врага**.
3. Если у меня нет открытых ранений друга и я могу — **погрести**, но только если у меня есть вода (или весло для +1 выбора, или зонтик).
4. Иначе если есть весло без воды — **бездельничать** (греблю избегать без подстраховки от жажды).
5. Иначе — **бездельничать**.

Шкет: предпочитает свою способность над обычным `rob`, если у цели есть закрытые карты.

#### Row: выбор оставляемых карт

- Просматривает 2-4 карты.
- Применяет «оценку» к каждой (negative / positive):
  - Чайка → +5
  - Перечёркнутая чайка → -3
  - «За борт» с моим именем → -10
  - «За борт» с именем врага → +5
  - «Жажда» с моим именем → -5 (если есть вода → -2)
  - Вёсла/силач → зависит от того, грёб ли бот сам
- Оставляет 1-2 карты с наивысшей суммой; если все ниже -8 — оставляет 0 (всё в низ колоды).

#### Свопы / ограбления — реакция

- Если у меня сила >= сила атакующего → отказать (драка выиграется).
- Если у меня сила < сила атакующего, но я могу позвать сильного союзника (друга) → отказать (надеюсь на союз).
- Иначе → согласиться, отдать с минимальной потерей.

Логика подбора кому отдать припас при rob:
- Если есть открытое — отдать наименее полезное (картины, дешёвые ценности).
- Если закрытое — атакующий вытянет случайную, бот не выбирает.

#### Драка — вербовка

Атакующий зовёт союзника:
- Если бот = друг атакующего → согласиться, добавить оружие.
- Если бот = враг атакующего → отказать.
- Иначе → отказать (бот не торгуется).

#### Драка — оружие

Все открытые оружия — добавлены автоматически. Закрытые оружия — открывать, если это меняет исход боя (бот вычисляет ожидаемые силы сторон).

#### Evening: выбор карты навигации

- Из доступных кандидатов (от гребцов и/или компас) — по той же scoring-функции, что и в row.
- Бот учитывает, что он на корме, и его враг ещё на воде → может предпочесть карту, где враг страдает.

#### Evening: shark_bait

- Если у меня открыта приманка И за бортом мой враг → **использовать**.
- Иначе — не использовать.

#### Evening: water

- При жажде: использовать на себя, если иначе ранение.
- Если есть лишняя вода и друг страдает — отдать другу.
- Без сознания друг + жажда → отдать ему свою воду (это спасает от смерти).
- Никогда — на врага.

#### Reactive: life_ring

- Если падаю за борт И есть life_ring (открытый или закрытый) И я без сознания → **открыть и использовать** (спасает от смерти).
- Если в сознании и есть life_ring → использовать, чтобы не потерять открытые припасы.

## 3. Архитектурная заметка

Бот **не имеет** доступа к чужим закрытым картам / чужим друзьям/врагам. Он принимает решения на тех же данных, что и человеческий клиент. Это важно:
- Бот «не жульничает».
- Можно безопасно использовать те же `Action`-валидации.
- При желании можно подменить бота на человека (или наоборот) — game continues.

## 4. Что делать когда бот ожидается, а bot.decide() возвращает невалидный Action

- Host пропускает действие, бот делает **SKIP** или эквивалент.
- Логирует ошибку для отладки.
- Не падает.

## 5. Реализация на старте

Положить в `src/bots/simple-bot.ts` один класс `SimpleBot implements Bot`. Принимает `playerId` в конструкторе.

```ts
class SimpleBot implements Bot {
  constructor(private readonly playerId: PlayerId) {}
  
  decide(state: FilteredGameState): Action {
    const phase = state.phase;
    switch (phase.type) {
      case 'morning': return this.chooseSupplyToKeep(state);
      case 'day': return this.dayDecision(state);
      case 'evening': return this.eveningDecision(state);
      default: throw new Error('unexpected phase for bot decide: ' + phase.type);
    }
  }
  
  // ... приватные методы по подфазам
}
```

## 6. Тестирование ботов

Не пишем сложных тестов. Прогон полной партии 4 бота × N раз и проверка:
- Игра завершается за разумное число дней (< 50).
- Нет деадлоков (бесконечных подфаз).
- Нет невалидных Action'ов от ботов.
- Подсчёт очков работает.

Это и есть наш integration-test игровой логики.

## 7. Что НЕ делать на MVP

- Не делать машинное обучение, MCTS, минимакс.
- Не учитывать неявные сигналы (раскрытие припаса другим игроком как «угрозу»).
- Не моделировать вероятности оставленных карт.
- Не пытаться блефовать или манипулировать.

Этого можно добавить потом, когда захочется одиночной игры против сильных ботов. На MVP — «лучше тупо, чем сложно».
